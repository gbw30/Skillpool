# SkillPool

Rebuild of the UF OSC MiniHacks (Sept 2025) project: ask who should staff a project, get named
people with cited passages. GraphRAG on Neo4j (vector + graph walks, reciprocal rank fusion).
Requirements: docs/PRD.md. Design and implementation status: docs/SPEC.md (section 0 and 14).
Run, test, deploy: README.md. Read those before planning; don't duplicate them here.

## Layout
- service/ — FastAPI + CLI (Python 3.12, uv). Models: Claude Haiku 5.5 (`claude-haiku-5-5`) for
  extraction/answers. Embeddings: `EMBED_PROVIDER` = `voyage` (voyage-4-lite, 1024-d,
  default) or `openai` (text-embedding-3-small, 1536-d); run `skillpool reembed` after switching.
- web/ — Next.js 16 (App Router, cacheComponents) UI + signed proxy (`app/api/[...path]`).
  The whole site sits behind `SITE_ACCESS_CODE` (`proxy.ts`, `lib/access.ts`, `/access`).
  Tailwind 4 with tokens in `app/globals.css`, Motion springs, three.js only on the landing page.
  The look is "Nocturne": warm black, cream serif headlines, one brass accent. On a wide screen the
  3D brain rises from the bottom edge of the home page under the question ("Horizon").
  Design decisions: `.plans/frontend-revamp-spec.md`.
  Read web/AGENTS.md and current Next.js docs before writing web code.
- "Open source" serves uploads from the bucket; documents loaded with `ingest-dir` link to
  `SOURCE_BASE_URL` (the corpus folder on GitHub) and answer 404 without it.
- With `UPLOADS_ENABLED` not `true`, `/upload` redirects home (`proxy.ts`, at once) and its links
  are hidden (`uploadsOn()` in the layout and landing page, decided at build time).
- corpus/ — one made-up company, all generated by `generate.py` (seed 7, no model calls): 136
  resumes, 241 project and company documents, ground truth in truth/. Never hand-edit the output.

## Commands
- Tests: `cd service && uv run pytest` (94 pass). Pipeline tests need
  `SKILLPOOL_TEST_NEO4J_URI=bolt://127.0.0.1:17687 SKILLPOOL_TEST_NEO4J_PASSWORD=skillpool-dev` and
  wipe that database, including the day's spend record.
- Local Neo4j: `docker compose up -d neo4j` (ports 17474/17687, auth neo4j/skillpool-dev).
- Web: `cd web && npm run lint && npm run build`.
- UI without keys or services: `cd web && npm run dev:mock` (canned data from `web/lib/mock.ts`).

## Invariants
- Every extracted fact needs a verbatim quote; answers cite chunks and are validated per sentence.
- Cypher is fixed and parameterized (named constants in service/skillpool/graph.py); never build
  Cypher from model output.
- Request signing (`signing.py`) must stay identical to `web/lib/service.ts`.
- An answer sentence with no citation may bring in no link, markup or name the evidence lacks.
  An upload never changes a person's name or title on record. Security design and its limits:
  docs/SPEC.md section 13.
- Two resumes are two people unless emails match; people listed separately in one document are
  never merged. One exception: an initial and the single full name it fits in the same document
  are one person, unless a job title or an email differs.
- Search ranks the skill list by skills matched, total level, then highest single level, and the
  project list by projects named, then skills used. Whoever is still equal goes by text
  similarity, then name (`_ranked` in `retrieve.py`), never by id: ids are random, so a rebuild
  would otherwise change the ranking.
- After fusion, people are reordered by evidence (`_by_evidence`): own skills matched plus named
  projects, then skills reached through projects too, then levels. The written answer sees only
  the top 5 and is told this order; change the two together, or the answer contradicts the list.
- A name alone never merges, and never creates a second person either: the mention is kept as
  unconfirmed (`MAY_MENTION`), shown on the person's page and not counted as evidence. It is saved
  (`Pending`) and tried again after every later batch, without a model call.
